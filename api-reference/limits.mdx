## Rate limits

You can request data depending on your data plan and account balance (default: `10000/month`). Pricing depends on the operation and the number of results returned, and may increase with additional data flags. For exact pricing, see each endpoint's **Pricing** section or your [billing settings](https://beta.generect.com/settings/billing).

## Parallel requests limit
- [Company search](/api-reference/endpoint/search/realtime-companies) — `POST /search/*/companies/`: 20 requests

- [Company enrichment](/api-reference/endpoint/enrich/enrich-realtime-company) — `POST /enrich/*/company/`: 50 requests

- [Lead search](/api-reference/endpoint/search/realtime-leads) — `POST /search/*/leads/`: 50 requests

- [Lead enrichment](/api-reference/endpoint/enrich/enrich-realtime-lead) — `POST /enrich/*/lead/`: 500 requests

- [Preview](/api-reference/endpoint/preview/preview-leads) — `POST /preview/leads/` and `POST /preview/leads/count/`: 100 requests

- [Profile resolve](/api-reference/endpoint/profiles/resolve) — `POST /profile/resolve/` and `POST /profile/resolve/bulk/`: shares the lead-enrichment budget above. A bulk call counts as **one** request against it, whatever number of profiles it carries.

## Recommended timeouts
- [Company search](/api-reference/endpoint/search/realtime-companies): 300 seconds

- [Company enrichment](/api-reference/endpoint/enrich/enrich-realtime-company): 60 seconds

- [Lead search](/api-reference/endpoint/search/realtime-leads): 300 seconds

- [Lead enrichment](/api-reference/endpoint/enrich/enrich-realtime-lead): 100 seconds

## Which endpoints are rate-limited

The parallel-request limits above apply to **search**, **enrich**, and **Preview** endpoints. **Email Finder, Email Validation, Phone Finder, bulk jobs, search count endpoints, and account/webhook endpoints have no parallel-request cap** — they are bounded only by your balance and, for bulk jobs, the [50-item limit per request](/use-cases/api/bulk-processing).

Both Preview endpoints share one 100-request budget, including the free `POST /preview/leads/count/`.

Limits are enforced per **API token + source IP**, per operation type. Exceeding one returns HTTP `429` — see [Errors](/api-reference/errors) — so retry with **exponential backoff**.

## Batch size caps

- **Bulk jobs** (enrich bulk, email find bulk, phone find bulk) and [`POST /profile/resolve/bulk/`](/api-reference/endpoint/profiles/resolve-bulk): up to **50 items** per request; a larger array is rejected with `400`.
- **`POST /email/validate/`** has no fixed array cap, but it is a synchronous endpoint — response time grows with batch size. Keep batches to **~50 emails** per request and parallelize, matching the bulk-endpoint convention.

### Reading the headers

Every response on a rate-limited operation carries:

| Header | Meaning |
| --- | --- |
| `X-RateLimit-Limit` | Requests you may have **in flight at once** for this operation |
| `X-RateLimit-Remaining` | Free slots at the moment the response left |
| `X-RateLimit-Scope` | Which cap applied — the caps are per operation, not per plan |
| `Retry-After` | Sent on `429` only |

<Warning>
These are **not** a windowed quota. `Remaining` is a gauge of what you currently have open, and it climbs again as your own in-flight requests finish — it does not refill on a schedule, and there is deliberately no `X-RateLimit-Reset`. An SDK that reads `Remaining` as "requests left this minute" will pace itself against the wrong thing.

For the same reason, a `429` here does not call for long exponential backoff: a slot frees the instant one of your in-flight requests finishes, which is what `Retry-After` reflects. Retry on that interval and keep your concurrency below `X-RateLimit-Limit` instead.
</Warning>

## Capacity limits on live data

Real-time single-lead enrichment and real-time search can also return `429` during exceptionally high live-source load — a temporary capacity guard, separate from the parallel limits above. Handle it the same way: back off and retry.

<Info>Limits apply per operation type and cover both database and realtime modes. They can be increased upon request.</Info>
